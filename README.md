# المساعد المحاسبي (Accounting Assistant)

نظام ويب خفيف وسريع يعمل كمساعد محاسبي للاستخدام في بيئة العمل — بواجهة عربية كاملة (RTL)
وتصميم احترافي هادئ. يدعم الفواتير، الإيرادات والمصروفات، القيود المحاسبية، إدارة المهام،
التقارير المالية، وتحويل الأرقام إلى كلمات عربية.

## المميزات

- **لوحة تحكم**: إجمالي الإيرادات والمصروفات وصافي الربح والضريبة، عدد الفواتير، المهام
  المستحقة والمتأخرة، وملخص شهري بياني.
- **حاسبة محاسبية**: عمليات أساسية، نسب مئوية، خصومات، ربح وهامش، وحساب الضريبة (إضافة
  واستخراج).
- **الفواتير**: إنشاء فواتير بعدة بنود مع كمية وسعر وحدة وخصم لكل بند، حساب الضريبة والإجمالي
  تلقائيًا، حالة سداد (مدفوعة/غير مدفوعة)، بحث وتصفية، ومعاينة/طباعة الفاتورة. كل فاتورة
  تُنشئ أو تُحدّث تلقائيًا قيدًا محاسبيًا مرتبطًا بها (مدين العملاء، دائن المبيعات والضريبة).
- **العملاء**: قائمة عملاء بأرقام تواصل، تُنشأ تلقائيًا من اسم العميل عند حفظ أي فاتورة، مع
  عرض الرصيد المستحق من الفواتير غير المدفوعة لكل عميل.
- **الموردون**: قائمة موردين، تُربط اختياريًا بعمليات المصروفات مع حالة سداد، وتعرض المبلغ
  المستحق لكل مورد من المصروفات غير المسددة.
- **دليل الحسابات**: شجرة حسابات محاسبية كاملة (أصول، خصوم، حقوق ملكية، إيرادات، مصروفات)
  قابلة للإضافة والتعديل والحذف، بحسابات رئيسية وفرعية، تُستخدم في القيود المحاسبية.
- **الإيرادات والمصروفات**: تسجيل العمليات مع تصنيف قابل للتخصيص بالكامل، تعديل وحذف،
  وإجماليات تلقائية.
- **القيود المحاسبية**: تسجيل قيود بعدة سطور (حساب / مدين / دائن) مع تحقق تلقائي فوري من
  توازن إجمالي المدين والدائن قبل الحفظ. القيود التلقائية الناتجة عن الفواتير محمية من
  التعديل المباشر (يُعدَّل مصدرها — الفاتورة — بدلًا من ذلك) لضمان تطابق الدفاتر دائمًا.
- **إدارة المهام**: إضافة مهام بتاريخ استحقاق وأولوية وحالة، مع رصد تلقائي للمهام المتأخرة.
- **تحويل الأرقام إلى كلمات عربية**: مناسب لكتابة المبالغ في السندات والفواتير (مثال: 1250 ←
  "ألف ومئتان وخمسون ريالاً... ").
- **التقارير**: تقرير الإيرادات، المصروفات، الأرباح والخسائر، الضريبة، والتقرير الشهري.

## التقنيات المستخدمة

React + Vite + Tailwind CSS + React Router — بدون أي مكتبات رسوم بيانية ثقيلة (الرسم
البياني الشهري مرسوم يدويًا بـ SVG) لإبقاء حجم المشروع صغيرًا وسريع التحميل.

## بنية المشروع

```
src/
├── lib/                   منطق حسابي وتنسيقي مستقل عن الواجهة (يمكن اختباره بمعزل عنها)
│   ├── storage.js          طبقة الوصول للبيانات (localStorage حاليًا — انظر القسم أدناه)
│   ├── calculations.js     كل العمليات الحسابية المحاسبية (جمع/طرح/ضرب/قسمة، ضريبة، هامش ربح...)
│   ├── numberToWords.js    تحويل الأرقام إلى كلمات عربية
│   ├── aggregate.js        تجميع البيانات لأغراض لوحة التحكم والتقارير
│   ├── format.js           تنسيق العملة والتواريخ والأرقام
│   └── id.js                توليد معرّفات فريدة
│
├── context/
│   └── SettingsContext.jsx إعدادات النظام (اسم المؤسسة، نسبة الضريبة، ترقيم المستندات)
│
├── hooks/
│   └── useCollection.js    خطاف عام للعمليات (إضافة/تعديل/حذف/عرض) على أي مجموعة بيانات
│
├── data/
│   └── defaults.js         قوائم افتراضية قابلة للتعديل بالكامل (تصنيفات، حسابات، أولويات)
│
├── components/
│   ├── ui/                  مكونات واجهة عامة (أزرار، حقول، جداول، نوافذ منبثقة...)
│   ├── layout/               الشريط الجانبي والرأس والتخطيط العام
│   ├── invoices/              نماذج ومعاينة الفواتير
│   ├── journal/                نموذج القيد المحاسبي
│   └── charts/                  رسم بياني بسيط بـ SVG
│
└── pages/                    صفحات النظام الرئيسية (لوحة التحكم، الفواتير، المصروفات...)
```

## طريقة التشغيل محليًا

يتطلب تثبيت [Node.js](https://nodejs.org) (الإصدار 18 فأعلى).

```bash
# 1) تثبيت الحزم
npm install

# 2) تشغيل بيئة التطوير (مع تحديث فوري للتغييرات)
npm run dev

# 3) بناء نسخة الإنتاج
npm run build

# 4) معاينة نسخة الإنتاج محليًا
npm run preview
```

بعد تشغيل `npm run dev` افتح الرابط الذي يظهر في الطرفية (عادة `http://localhost:5173`).

## رفع المشروع على GitHub


> ملحوظة: مجلدي `node_modules` و`dist` مستثنيان بالفعل عبر `.gitignore` ولن يتم رفعهما.

### النشر على GitHub Pages

المشروع يستخدم `HashRouter` عن قصد (الروابط تكون بصيغة `#/invoices` مثلًا)، ومسارات
الملفات في `vite.config.js` مضبوطة كمسارات **نسبية** (`base: './'`) — أي أن المشروع يعمل
تلقائيًا سواء نُشر على جذر النطاق (`username.github.io`) أو داخل مجلد فرعي
(`username.github.io/اسم-المستودع/`) دون أي تعديل يدوي إضافي.

⚠️ **الخطأ الأكثر شيوعًا**: نشر الكود المصدري كما هو (بدون بناء) — يظهر عندها خطأ
`Failed to load resource: main.jsx 404` لأن GitHub Pages يعرض ملفات ثابتة فقط ولا ينفّذ
`npm run build` بنفسه. يجب دائمًا نشر محتوى مجلد `dist` (الناتج بعد البناء)، وليس مجلد `src`.

**الطريقة الموصى بها (تلقائية، بدون أخطاء يدوية):**

المشروع يتضمن ملف `.github/workflows/deploy.yml` جاهزًا يقوم بالبناء والنشر تلقائيًا مع
كل `push` على فرع `main`. الخطوات:

1. من إعدادات المستودع على GitHub: **Settings → Pages → Build and deployment → Source**،
   اختر **GitHub Actions** (وليس "Deploy from a branch").
2. ادفع (`push`) الكود إلى فرع `main` كالمعتاد — سيقوم GitHub تلقائيًا بتنفيذ البناء
   ونشر مجلد `dist` الناتج.
3. بعد دقيقة أو دقيقتين، سيظهر رابط الموقع في تبويب **Actions** وفي **Settings → Pages**.

**الطريقة اليدوية (بديلة):**

```bash
npm run build
```
ثم ارفع **محتوى مجلد `dist`** فقط (وليس المشروع كله) إلى فرع `gh-pages`، أو اضبط GitHub
Pages ليعمل من مجلد `dist` مباشرة.

## تخزين البيانات وربطها لاحقًا بقاعدة بيانات حقيقية

جميع البيانات محفوظة حاليًا داخل `localStorage` في متصفح المستخدم فقط (لا خوادم، لا حسابات،
لا اتصال بالإنترنت مطلوب). هذا مقصود ليعمل النظام فورًا دون أي إعداد.

كل الشاشات تتعامل حصريًا مع الدوال الموجودة في `src/lib/storage.js`
(`getAll`, `getById`, `create`, `update`, `remove`, `replaceAll`) ولا تتعامل مع
`localStorage` مباشرة في أي مكان آخر. لذلك، لربط النظام لاحقًا بقاعدة بيانات حقيقية
(مثل Firebase أو Supabase أو REST API خاص)، يكفي إعادة كتابة الدوال داخل هذا الملف فقط
لتتصل بالخادم بدلًا من `localStorage`، دون الحاجة لتعديل أي صفحة أو مكوّن آخر في المشروع.

يوفر النظام أيضًا من صفحة **الإعدادات** زر لتنزيل نسخة احتياطية كاملة من البيانات بصيغة
JSON، وزر لاستيرادها مرة أخرى — مفيد عند تغيير الجهاز أو قبل مسح بيانات المتصفح.

## نسبة الضريبة

نسبة ضريبة القيمة المضافة **قابلة للتغيير بالكامل** من صفحة الإعدادات، وليست مثبّتة داخل
الكود. جميع نتائج الحسابات الضريبية في النظام هي أداة مساعدة للحساب فقط، وليست إقرارًا
ضريبيًا رسميًا — يُرجى مراجعة هيئة الزكاة والضريبة والجمارك عند إعداد الإقرارات الرسمية.

## الأمان

لا يحتوي المشروع على أي مفاتيح API أو كلمات مرور أو بيانات اتصال بخدمات خارجية. كل شيء
يعمل محليًا بالكامل.
